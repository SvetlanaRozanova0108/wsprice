# Проценка — подбор автозапчастей и аналогов

Клиентское SPA на **React + Redux** для Web-сервиса «Проценка» (`api.favorit-parts.ru`).
Интерфейс реализует двухэтапный подбор номенклатуры:

1. **Поиск производителей** — ввод артикула, запрос к API, список брендов.
2. **Аналоги и предложения** — выбор производителя, повторный запрос с `brand` и `analogues=on`, таблица позиций с ценой и остатками по складам.

Проект написан на JavaScript (без TypeScript), стилизация — Bootstrap 5 + собственные CSS-переменные.

## Запуск

Требуется Node.js 20+ и npm.

```bash
npm install
npm run dev
```

Приложение откроется на `http://localhost:3000`.

Сборка production-версии:

```bash
npm run build
npm run preview
```

## Ключ API

По умолчанию используется демонстрационный ключ из документации:

```
00000000-0000-0000-0000-000000000001
```

Ключ можно изменить двумя способами:

- в интерфейсе — блок **«Настройки подключения»** под полем артикула (ключ сохраняется в `localStorage` браузера);
- через переменные окружения — скопируйте `.env.example` в `.env` и укажите `VITE_API_KEY`.

Для реальной работы нужен ключ покупателя, выданный favorit-parts.ru. Демо-ключ подходит для проверки сценария и примеров `0189`, `7160500039S`.

## Как это работает

### Этап 1. Артикул → производители

Запрос:

```
GET /hs/hsprice/?key=...&number=0189&info=on
```

Ответ API содержит массив `goods`. Клиент:

- отбрасывает «пустую» позицию, которую сервис возвращает при отсутствии детали;
- группирует товары по бренду;
- показывает количество, число предложений и минимальную цену по складам;
- выводит карточки производителей.

### Этап 2. Производитель → аналоги

Запрос:

```
GET /hs/hsprice/?key=...&number=0189&brand=CAFFARO&analogues=on&info=on
```

Клиент объединяет исходную позицию и вложенный массив `analogues`, убирает дубликаты и строит таблицу:

- название, производитель, артикул;
- **цена** — минимальная цена среди складов с положительным остатком (поле `goods.price` не используется, как требует документация);
- **остаток** — общее количество по складам (`count`);
- раскрывающаяся строка с детализацией по каждому складу: цена, остаток, дата отгрузки, признаки «свой склад» и «без возврата».

Доступны фильтр по названию/бренду/артикулу, переключатель «Только в наличии», сортировка и постраничный вывод (20 позиций на страницу).

## Обработка состояний

| Ситуация | Поведение интерфейса |
| --- | --- |
| Запрос выполняется | Компонент `Loader` со спиннером и skeleton-строками; кнопка поиска блокируется |
| Сеть недоступна | `ErrorAlert` с понятным сообщением и кнопкой «Повторить» |
| HTTP-ошибка (403/500 и т.п.) | Пытаемся прочитать JSON с полем `error`, иначе показываем статус ответа |
| Ошибка API (`error`) | Сообщения маппятся на русский: неверный ключ, пустой номер, превышение квоты |
| Деталь не найдена | Пустой массив `goods` или пустая структура → `EmptyState` |
| Аналоги не найдены | Пустой список позиций → предложение вернуться к производителям |
| Устаревший ответ | Защита через `requestId` в Redux: результат старого запроса не перезаписывает новый |

## CORS и production

API работает по **HTTP** и отдаёт `Access-Control-Allow-Origin: *`. В dev-режиме Vite проксирует запросы:

```
браузер → http://localhost:3000/hs/hsprice/ → http://api.favorit-parts.ru/hs/hsprice/
```

Это настроено в `vite.config.js` (и для `dev`, и для `preview`), поэтому CORS-проблем нет.

Для production рекомендуется поставить приложение за reverse proxy (nginx и т.п.) и проксировать `/hs/hsprice/` на API. Это также решает проблему mixed content, если сайт открывается по HTTPS: браузер заблокирует прямой HTTP-запрос со страницы HTTPS. Альтернатива — задать полный адрес в `VITE_API_BASE`, но тогда приложение должно работать по HTTP либо API должен быть доступен по HTTPS.

Пример nginx:

```nginx
location /hs/hsprice/ {
    proxy_pass http://api.favorit-parts.ru/hs/hsprice/;
    proxy_set_header Host api.favorit-parts.ru;
}
```

## Примечания

- Ключ покупателя и запросы видны в DevTools — это особенность GET-API, а не приложения.
- У сервиса есть лимит запросов (ошибка `Request quota exceeded!`), поэтому поиск выполняется по кнопке/Enter, без live-запросов на каждое нажатие клавиши.
- Цены и остатки показываются на момент запроса и не кешируются.
